About This Tool

What this is: a warning verification browser for storm-based warnings — Tornado (TOR), Severe Thunderstorm (SVR), Flash Flood (FFW), Snow Squall (SQW), Special Marine Warning (SMW), and Dust Storm Warning (DSW) — built on top of the Iowa Environmental Mesonet's IEM Cow service. IEM Cow automatically checks each storm-based warning polygon against Local Storm Reports (LSRs) to determine whether it verified.

Warning types to track: Settings has a picker for which of the 6 phenomena above are actually queried and shown, capped at 4 so the queue-card grid always stays a clean 2×2 — not every office deals with Snow Squalls, Special Marine Warnings, or Dust Storm Warnings. Special Marine Warning's and Dust Storm Warning's "misses" filtering in the Trends phenomena filter both use a best-effort LSR type guess (wind gust/damage codes) rather than a confirmed one — flagged in the code if either needs correcting later.

Verification status shown here is computed as: Verified if IEM found a matching LSR of the right type, within the time window, inside the buffered warning polygon. Needs Verification if the warning has fully expired with no matching LSR found. Pending if the warning is still active (verification isn't final until it expires or a report comes in).

Calendar day: dates here are bounded by local midnight in the configured timezone (Settings), not 00Z UTC — so an overnight event isn't split across two different "days" the way a strict UTC day would.

Confidence score: the percentage shown per-warning is a simple, unofficial heuristic (based on lead time and number of matching reports) meant to give a quick visual sense of how solid the verification is — it is not an NWS or IEM statistic.

Data is unofficial. Per IEM's own disclaimer, this data is intended for educational/situational-awareness use, not as an official verification record.

Switching offices: the office dropdown in the header lists every NWS Weather Forecast Office nationwide (sourced live from IEM's own WFO network table) — pick one and the app re-queries live NWS zone boundaries for that office and re-centers the map.

Date ranges: the Archive picker loads every matching warning and LSR for the whole range directly onto the map, table, and stats (using the same boundary-safe padding logic as single-day view), rather than just showing a summary.

Basemap: CartoDB Voyager. Zone boundaries: official NWS zone reference service (mapservices.weather.noaa.gov). Office list: IEM WFO network table. Radar: IEM's time-enabled NEXRAD composite reflectivity WMS, snapped to the nearest 5-minute composite (archive available back to Feb 16, 2011). Map library: Leaflet.

PDS / Emergency badges: the two are detected differently. Emergency (Tornado/Flash Flood) comes from IEM's own structured registry of every Emergency on record since 1999 — a direct lookup, not limited by view size, so it works correctly even across a full-year Archive range. PDS has no equivalent structured IEM field, so it's still detected by scanning each warning's product text for "PARTICULARLY DANGEROUS SITUATION" wording, which is why it's skipped for very large date ranges (75+ warnings) to avoid a burst of full-text fetches — it still works normally for a single day or a short range, and selecting an individual warning always loads its own text regardless. If the Emergency registry ever fails to load, Emergency detection quietly falls back to the same text-scan PDS uses, within that same size limit.

Keyboard shortcuts: ← / → previous/next day, j / k step through the warnings table, n jump to the next unverified warning, Esc close dialogs.

Sharing a view: the URL updates automatically with the current office and date (or range), so copying the address bar link takes someone straight to the same view.

PNG export: captures the queue, table, summary, stats, and warning-details panels, plus the warning polygons/zone lines/LSR markers on the map — but not the basemap street imagery itself, since CartoDB's tile server doesn't allow that imagery to be read back into an exported image. Use "Print" instead for a version with full basemap tiles included.

Year heatmap: the Trends modal's "1 Year" option shows a GitHub-style calendar grid colored by that day's CSI — click any cell to jump straight into that day.

Counties tab: a ranked breakdown of which counties/zones see the most warnings and their false-alarm rate for the current day or range.

Analytics tab: eleven charts built entirely from whatever's already loaded for the current day or Archive range — no extra IEM requests beyond the ones already made. Timeline is a Gantt-style view of every warning's issue→expire span, click a bar to open it. Diurnal and Duration show issuance-by-hour and warning-length distributions, stacked by phenomena. LSR Source breaks down who submitted the verifying reports (spotter, public, law enforcement, etc. — per IEM's own field). Tag vs. Verified and Polygon Size bucket warnings by their tagged threat value or polygon size and show verification rate per bucket, with sample size labeled since a rate from a couple of warnings reads very differently than one from dozens. Time-of-Day Skill splits POD/FAR/CSI into four-hour local blocks — small samples on a single day, more meaningful loaded over a wide Archive range. PDS/Emergency Impact compares verification rate for PDS/Emergency-tagged Tornado and Flash Flood warnings against non-tagged ones. mPING Categories breaks down loaded mPING reports by type (only available when the mPING toggle is on). Continuation Chains reuses the same "Possibly Related Warnings" heuristic from the details panel to tally how much of the view was isolated one-shot warnings vs. clustered sequences. Office Comparison shows a per-office verification rate side by side — only meaningful with Compare Offices active, since unwarned LSRs aren't individually attributed to a specific office in this data.

Live mode: while viewing today, the app quietly re-polls IEM every few minutes and toasts new warnings as they're issued — a red "LIVE" badge next to the date shows it's active. It turns off automatically for any other day or a date range.

Accessibility: modals trap focus and return it on close, icon-only controls carry aria-labels, and Settings has a colorblind-safe palette toggle for the status colors. The summary donut, warning timeline, and year heatmap all carry text equivalents for screen readers, and the heatmap is keyboard-operable. Above ~1000px wide, the left/right panels resize fluidly with the window instead of staying a fixed pixel width; below that, the layout reflows to a single stacked column for laptops, tablets, and phones.

Compare Offices: overlay up to 3 additional WFOs on the same map/table/stats as the primary office — useful for outbreaks that cross office boundaries. Warnings show a small office tag when active. Large loads (a wide date range, several offices, or the 1-year heatmap) are split into chunks with progress shown in the status bar, rather than one silent request.

Related warnings: the details panel lists other warnings sharing a county and issued within 30 minutes of the selected one. This is a timing/geography heuristic only — IEM Cow doesn't expose an authoritative "this warning replaced that one" link — so treat it as a lead, not a confirmed sequence.

Settings portability: Settings has Export/Import buttons for carrying your thresholds, timezone, colorblind preference, and recent-office list to another browser or machine — everything here is stored locally in this browser, there's no server-side account.

Warning Meteorologists: the stats panel shows a count of distinct forecaster codes active in the window — intentionally an aggregate, not a per-person breakdown, since named scorecards aren't something this tool is meant to produce.

Tagged Threat: the warning details panel shows the forecaster's windtag/hailtag from the warning's IBW tags at issuance, alongside the peak magnitude actually seen in the matched LSRs below it — a quick "was the tag well-calibrated" comparison, not a pass/fail judgment.

Polygon quality metrics (bottom of the stats panel): Avg Polygon Size and Polygon vs Avg County Size are computed locally from the same calendar-day-corrected warning set as everything else here (the county comparison is against the CWA's average county size, not each warning's own specific county — a rough yardstick, not an exact ratio). Area Verified, Shared Border, and TOR Reports Outside Co-located SVR come directly from IEM Cow's own computation instead, since replicating its exact verification-area and border-matching logic isn't practical here — these three specifically reflect IEM's own queried window, which includes the ~6 hour boundary padding described above, so treat them as close-but-not-exact for the precise calendar day. A high Shared Border % is a rough proxy for "box warnings" that follow county lines rather than the storm.

Lead Time Distribution: the histogram at the bottom of the stats panel buckets every matched report's lead time into 5-10 minute bins, stacked by phenomena color (matching the queue cards/warning polygons) when more than one phenomena is present, so a wide or bimodal spread doesn't get hidden behind the single averages above it.

Confidence score: shown in a verified warning's details panel — a simple, unofficial heuristic based on matched report count and lead time, meant for a quick visual read on how solid that particular verification looks. Not an NWS or IEM statistic.

Linking to a specific warning: selecting a warning updates the address bar to point straight at it (in addition to the office and date/range it already tracked), and the "🔗 Copy Link" button in the details header copies that URL directly — useful for case reviews or training files where you want to point someone at one specific warning rather than a whole day.

Tagged Threat Accuracy: below Warning Meteorologists in the Verification tab, this rolls up every wind/hail-tagged warning's tag against its peak verified magnitude for the day/range, averaged — surfacing a systematic bias (consistently over- or under-tagging) that's invisible when only looking at one warning's Tagged Threat line at a time.

Trends phenomena filter: the Trends modal can be narrowed to a single phenomena (TOR/SVR/FFW/SQW) instead of always blending all four together — useful for checking whether, say, flash flood POD is trending differently than tornado POD. Misses are narrowed along with it, matched to that phenomena's own LSR types, so the POD/FAR/CSI shown stay internally consistent rather than mixing a filtered numerator with an unfiltered denominator.

Summary Report (📄 icon): generates a standalone, formatted, printable report for whatever's currently loaded — a single day or a full Archive range — covering overview counts, verification stats, lead time, tag accuracy, polygon quality, and top counties. It downloads as a self-contained HTML file with no dependency on this page, so it opens and prints cleanly on its own. Running a full year through Archive and generating this is effectively an annual summary, rather than a separate reporting mode.

mPING reports: "Show mPING reports" overlays crowd-sourced weather reports from the mPING project (OU CIMMS / NSSL) alongside the LSR markers — separate dots, separate legend, own on/off toggle. Requests go through a small server-side proxy that holds the API key, so no visitor needs their own account; the key's license tier still applies, though, so if it's a Research-tier key, reports from the last 48 hours (including "today") won't show up. mPING reports are informal public submissions, not an official report source like LSRs — treat matches against warnings as a supplementary cross-check, not a verification input (IEM Cow's own verified/unverified status is unaffected by mPING data either way).
